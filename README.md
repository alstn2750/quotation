# folio

고객에게 제안할 다음 기회를 만드는 제안서·견적서 작성 웹 애플리케이션입니다. Node.js와 SQLite를 사용하며 런타임 외부 패키지 없이 실행됩니다.

## 시작하기

Node.js 22.13 이상이 필요합니다. 개발 환경에서는 Node.js 26.1로 검증했습니다.

```sh
npm install
npm start
```

브라우저에서 **http://localhost:3100**을 엽니다. `npm run dev`로 실행하면 서버 파일 변경 시 자동으로 재시작합니다. 기본값은 로컬 호스트 바인딩입니다.

## 구현된 기능

- 대시보드: 실제 저장 문서에 따른 문서 수, 작성 상태, 수주 합계, 최근 활동
- 제안서·견적서: 분야별 초안 생성, 섹션 수정, 고객사·일정·진행 상태 관리, 서버 저장
- 견적 편집: 항목 추가·삭제, 수량·단가 수정, 원 단위 반올림과 부가세 계산
- 문서: 검색, 상태 및 종류별 필터, 실시간 미리보기, 브라우저 인쇄/PDF 저장
- 템플릿: 브랜딩, 웹 개발, 마케팅, 컨설팅의 네 가지 디자인과 업무 범위
- 고객 관리: 고객사, 담당자, 이메일 등록과 고객별 새 제안 작성
- 계정: 이메일 회원가입·로그인·로그아웃, 회사명·사용자명 설정
- 워크스페이스: 사용자별 문서·고객·활동 데이터 분리
- 반응형 UI, 키보드 단축키, 모달 포커스 제한, 저장하지 않은 변경사항 안내

첫 방문에는 브라우저별 체험 워크스페이스와 5개의 샘플 문서가 생성됩니다. 회원가입하면 현재 워크스페이스가 계정으로 전환되어 샘플과 작업 문서가 그대로 보관됩니다. 체험 세션은 7일 동안 유지됩니다. 계정 등록 후에는 로그아웃하거나 다른 기기에서도 다시 로그인해 문서를 복원할 수 있습니다.

문서 상태의 ‘검토 대기’와 ‘수주 완료’는 사용자가 직접 관리하는 상태입니다. 이메일 전송이나 계약 체결이 자동 실행되는 것은 아닙니다. 수주 합계에는 ‘수주 완료’인 제안서와 견적서가 각각 포함됩니다. 동일 계약을 중복 표시하지 않도록 대표 문서 한 건에만 해당 상태를 지정하세요.

## 실제 AI 연결

프로젝트 루트에 `.env` 파일을 만들고 `.env.example`을 참고해 설정합니다.

```dotenv
HOST=127.0.0.1
PORT=3100
OPENAI_API_KEY=발급받은_API_키
OPENAI_MODEL=계정에서_사용할_수_있는_모델_ID
COOKIE_SECURE=false
```

`OPENAI_API_KEY`와 `OPENAI_MODEL`이 모두 설정된 경우 실제 AI 모드로 작동합니다. 모델은 Responses API의 Structured Outputs를 지원해야 합니다. 서버를 재시작하면 적용됩니다. API 키는 서버에서만 사용하며 브라우저나 SQLite에 저장하지 않습니다.

OpenAI Docs를 참고하여 [Responses API의 Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)로 제안서 섹션을 받도록 구현했습니다. 원시 REST 응답의 `output[].content[]`에서 텍스트를 읽으며, 거부·불완전 응답·시간 초과·API 오류를 처리합니다. 프로젝트명, 고객사, 설명, 일정, 업무 범위를 OpenAI에 전달하며 `store: false`를 사용합니다. 가격과 세금은 AI가 아닌 서버/화면 계산 코드에서 처리합니다.

키가 없으면 **샘플 모드**로 작동합니다. 입력한 내용을 선택한 템플릿에 반영하는 방식으로, AI가 생성했다고 표시하지 않습니다. 예산을 비워두면 공급가 1,000만 원의 예시 금액을 사용합니다. 0원은 0원으로 유지합니다. 실제 AI 호출은 API 키가 없는 상태에서 검증하지 않았습니다.

## 데이터와 구성

```text
server.js            HTTP 서버, 인증, API, AI 연동
lib/domain.js        견적 계산, 입력 검증, 템플릿, 샘플 생성
lib/store.js         SQLite 저장과 워크스페이스 데이터 접근
public/app.js        화면 구성, 에디터, 클라이언트 동작
public/styles.css    반응형 디자인과 A4 인쇄 스타일
public/index.html    웹 진입점
tests/               계산·API·브라우저 검증
data/folio.sqlite    최초 실행 시 자동 생성되는 데이터베이스
```

비밀번호는 랜덤 salt와 scrypt 해시로 저장합니다. 세션 토큰은 HttpOnly / SameSite 쿠키로 전달하고 DB에는 해시만 저장합니다. API에 사용자별 접근 제한, 인증·AI 요청 횟수 제한, 입력 크기 제한, 동일 출처 검사, SQL 파라미터 바인딩, HTML 출력 이스케이프를 적용했습니다. SQLite WAL 모드를 사용하므로 운영 백업은 SQLite 백업 방식 또는 서버를 중지한 상태로 수행하세요.

화면의 한글·영문 폰트는 Google Fonts에서 로드하며 네트워크가 없으면 시스템 글꼴로 대체됩니다. 문서 그래픽은 HTML/CSS/SVG로 제작했습니다.

## 검증

```sh
npm test
node tests/browser.mjs
```

`npm test`는 독립 임시 DB와 서버로 실행합니다. 견적과 부가세, 0원 예산, 유효성 검사, 사용자 간 접근 차단, 계정 재로그인과 데이터 보관을 확인합니다.

브라우저 검증에는 Playwright와 설치된 Chrome을 사용합니다. macOS에서는 기본 Chrome 경로를 사용하며 다른 환경에서는 `CHROME_PATH`를 설정할 수 있습니다. 기본으로 독립 임시 DB와 서버를 시작하며, 실행 중인 특정 서버를 확인하려면 `FOLIO_TEST_URL`을 지정합니다. 대시보드·에디터·모바일 스크린샷과 PDF는 OS 임시 폴더에 `folio-*` 이름으로 저장합니다.

## 외부 고객 공개 전 남은 범위

현재는 로컬에서 실행하고 검증할 수 있는 기능형 MVP입니다. 상용 서비스의 공개 배포나 결제는 연결하지 않았습니다. 공개 전에는 배포 환경에 맞춰 HTTPS와 `COOKIE_SECURE=true`, 이메일 인증·비밀번호 재설정, 결제·플랜별 사용량 관리, 체험 데이터 정리 정책, 고객 데이터 삭제·백업·복구, 운영 모니터링을 추가해야 합니다. 팀원 초대, 공동 편집, 고객 공유 링크, 이메일 발송, 전자서명도 현재 범위에는 포함하지 않습니다.
